# Downstream Drift Review — Hexalith.Works PRD

Reviewer: ad-hoc downstream-drift pass · Date: 2026-09-08 · Inputs: `prd.md` (HEAD `33a27e2`), `addendum.md`, `.decision-log.md`, sprint change proposals 2026-06-15 / 06-26 / 07-21 / 09-05 / 09-06, `architecture.md` (AD register + open-findings register), `epics.md`, `implementation-artifacts/deferred-work.md`, and `git diff 40d3603..HEAD` on the PRD folder.

## Preamble

The PRD is still the source of record for *product intent* — every PRD edit approved in the two September correct-course proposals landed (verified by git diff), the three earlier proposals approved no PRD edits, and the epics' FR inventory tracks the amended FR-7/FR-20/FR-21/FR-24 text. It is no longer the source of record for the *kernel's shape*: the 2026-09-06 architecture update introduced a second aggregate (AD-21 Work-Tree Registry) that takes parent/child edge ownership and the public spawn entry point away from the `WorkItem` aggregate, and declared its own register the "binding consistency contract … where prose and this register disagree, the register wins" — none of which was routed back through the PRD (§3, §4.1, FR-5, FR-13, FR-16, §14) or the decision log. Overall verdict: **material drift** — not superseded, but the PRD lags the architecture on one structural decision, its §13/§14 are stale, and its audit trail stops in June.

## Findings

- **[high]** Work-Tree Registry (AD-21) relocates tree-edge ownership and the spawn entry point without a PRD amendment (PRD §3 Glossary, §4.1, FR-5, FR-13, FR-16 ↔ `architecture.md` AD-21 lines 272–316, `epics.md` Epic 3 note lines 405–410, Story 3.2 lines 848–878) — PRD §3 defines the Work Item as "*the* aggregate root" that "owns … optional parent/children", §4.1 says the `WorkItem` aggregate "owns … its parent and children references", FR-13 says "Spawning enforces an acyclic, single-parent tree" and FR-16 says "A Work Item can spawn one or more children … `ChildSpawned` … emits on the parent." AD-21 now binds: "a tenant-scoped, event-sourced **Work-Tree Registry** aggregate … owns every `(tenant, childId) → parentId` edge and derives ancestry and depth from its own state"; "the **public entry point is the registry's reserve command**, and direct `SpawnChild` submission is restricted to the reactor's workload identity"; caller-supplied tree facts on `SpawnChild` "are demoted to **assertions**". The epics carry only a "pending additions" note on Epic 3; Story 3.2's ACs still make `SpawnChild` the caller-facing act, and Story 3.1 still tests the guard as the authority. The architecture even contradicts itself: its Requirements Overview (line 463) still describes FR-1–5 as "A single event-sourced aggregate root owning … parent/children refs". This is a product-visible change (a builder can no longer issue `SpawnChild`; a new command/event family enters the v1 contract; SM-C1 "don't grow the kernel" is engaged) and it went through the architecture workflow only. *Fix:* run a correct-course pass for AD-21: amend PRD §3 (Work Item is *an* aggregate root; add "Work-Tree Registry" glossary term), §4.1/FR-5 (Work Item *references* its parent/children; edge authority is the registry), FR-13 (guard enforced at registry reservation, `WorkItem` re-asserts), FR-16 (public act is the registry reserve; `SpawnChild` is reactor-internal; duplicate attached pair is a no-op), FR-7 (registry events + dedicated spawn-rejection event join the catalog additively), and §14 (the "enforced at spawn time" assumption). Correct `architecture.md` line 463. Update Stories 3.1/3.2 ACs or explicitly supersede them with the pending AD-21 story.

- **[medium]** Baseline security enforcement (AD-23/AD-24) is v1 scope the PRD says v1 does not build (PRD §5 Non-Goals, §6.2, §9 ↔ `architecture.md` AD-23 lines 344–368, AD-24 lines 370–395, AD-20 matrix R10) — PRD §5: "v1 builds … **no** security-hardening enforcement (step-up auth, consent/residency routing, DoS guards).
