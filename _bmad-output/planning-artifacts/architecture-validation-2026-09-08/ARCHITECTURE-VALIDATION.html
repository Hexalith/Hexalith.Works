Critical findings

VAL2-C01critical — The persisted roll-up document and its merge function are unbound; two writers will collide on one key

  • Issue: AD-06 binds the logical shape (one LWW slot per descendant, keyed by the descendant's own sequence) and AD-22 assigns the multi-document fan-out to the EventStore SDK while "Works owns the pure contribution/merge strategy". Neither names the persisted document type, the per-slot merge function, the seam signature the SDK calls, or that a document-level watermark is forbidden. The live document carries exactly such a watermark (LatestAcceptedSourceSequence) and the live dispatcher does document-level LWW; the live strategy still computes the rolled value by recursive in-memory traversal. The register presents the flattened slot document as [ADOPTED] when it is the AD-22 target.
  • Divergence/risk: An SDK fan-out that writes slots into an ancestor's key and a Works single-aggregate dispatch that keeps the higher-watermark document compare sequences across two streams — the precise failure AD-06 exists to forbid — and one overwrites the other wholesale. The RR-1 convergence property cannot hold across the two writers.
  • Source: architecture.md:82–95 (AD-06), :318–342 (AD-22), :263 (R4), :465 (retired formula still printed).
  • Corroborating evidence: WorkItemRollUp.cs:29–38 (single watermark, no slot map); WorkItemProjectionDispatcher.cs:446–457 (document-level LWW); WorkItemRollUpProjection.cs:234–265 (recursive fold); docs/work-roll-up-projection.md:94–100; IDomainProjectionHandler.cs:11–18 (stateless single-read-model seam, no fan-out contract to inherit). Registry-driven slot removal on detach/cancel is also impossible under "written only from its own descendant's stream" (ADV-11).
  • Found by: Adversarial ADV-01, ADV-11; conformance CONF-11; security SEC-07 (provenance check location).
  • Disposition: Autofix in Update for the register text (declare the persisted WorkItemRollUpDocument shape in Contracts with per-field merge: own fields LWW by own sequence, each slot LWW by its descendant's sequence only, no document-level gate; declare the IRollUpSlotMerge-style seam Works supplies and the SDK calls without comparing sequences; split AD-06 into adopted invariant vs target storage shape). Discuss which story replaces the live document. No change applied.

VAL2-C02critical — "Own contribution" is undefined and "computable from the event alone" is false

  • Issue: Everything in AD-06/AD-22 rests on "that descendant's own contribution per Unit", yet no AD defines the function, and AD-22 asserts the value is computable from the event alone. ProgressReported carries a delta; terminal → 0 needs status; a mismatched-Unit ReEstimated is retained-not-applied and unknowable from the event. The PRD amended today now also says explicit completion at Remaining > 0 contributes 0, unestimated items contribute 0 plus a count, and re-estimate below Done clamps. AD-07 still says only "Remaining 0 → Completed".
  • Divergence/risk: With the fan-out writer in the EventStore repository and the strategy in Works, the two compute different numbers for any item with prior progress, a re-estimate, a terminal transition, or mixed-Unit history — silent numeric corruption of every ancestor total (the SM-2 failure AD-06 exists to prevent), undetectable unless both units are tested together.
  • Source: architecture.md:82–95, :97–103 (AD-07), :318–326 (AD-22 premise), :336–337.
  • Corroborating evidence: WorkItemEffort.cs:26–36; WorkItemRollUpProjection.cs:222–232 (terminal → 0 from folded state); WorkItemState.cs:176–201; prd.md:202–203, 223, 239 (2026-09-08 completion rules).
  • Found by: Adversarial ADV-02; rubric walker RW-05.
  • Disposition: Autofix in Update. Add to AD-06 Binds: own contribution = clamped Remaining of the descendant's own effort, per Unit; 0 for any terminal status including explicit completion at Remaining > 0; 0 plus an unestimated count for an item with no estimate. Amend AD-22: the contribution slot is produced only by the descendant's own single-aggregate projection from folded state and transported by the fan-out, which never inspects Works payloads; a slot is emitted on every state-changing delivery including terminal transitions. Amend AD-07 for explicit completion. No change applied.

VAL2-H04high — Expiry cannot reuse the AD-11 index or name function as written, and a stale expiry reminder expires a live item

  • Issue: AD-25 says missed expiries reconcile "through the same indexed pending-source protocol as DateReached". Separately, cancellation of the old reminder on reschedule is best-effort and a new instant creates a second reminder rather than replacing the first; ExpireWorkItem carries no due-instant witness, so the clock-free Handle cannot refuse a stale fire.
