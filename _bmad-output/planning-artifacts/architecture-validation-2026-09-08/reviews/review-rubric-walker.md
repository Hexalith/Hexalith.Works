### RW-01 — [high] — AD-13 resume Rule contradicts AD-17's authoritative matrix and PRD FR-15

**Issue:** AD-13 Rule (architecture.md:163-164): "`ResumeWorkItem` is idempotent — no current match is a no-op; a duplicate is a no-op." AD-17 (:200) makes `docs/lifecycle-transition-matrix.md` authoritative for transitions, and that matrix (docs/lifecycle-transition-matrix.md:170-174) says a non-matching resume returns `WorkItemTransitionRejected` and only a repeat of the *consumed* condition is a no-op. PRD FR-15 (prd.md:285, 2026-09-08) and the addendum handoff H2 (addendum.md:62) state the same. The legacy prose repeats the wrong wording (:219, :838-840) and epics NFR-9 (epics.md:191-193) inherited it.
**Divergence/risk:** two register entries disagree, so the doc's own tiebreak ("register wins") cannot settle it. Adapter builders (AD-25 expiry reminder, Theme-3 external-signal adapter, the R6 reconciler, the R7 process-runner) reading AD-13 will expect a stale trigger to be silent; the aggregate persists a rejection instead. `DateReminderActor.cs:73-74` already encodes the AD-13 assumption ("the aggregate no-ops after the first WorkItemResumed") — true only when the same `DateReached` condition repeats, false when a child-completion resumed the item first. A builder writing retry policy or acceptance tests to AD-13 diverges from one writing to the matrix.
**Source:** architecture.md:159-164, :196-200, :219, :838-840.
**Corroborating evidence:** docs/lifecycle-transition-matrix.md:44, :165-174; prd.md:285; addendum.md:62; src/Hexalith.Works/Reminders/DateReminderActor.cs:73-74; epics.md:191-193.
**Suggested disposition:** autofix — rewrite AD-13 Rule to "a resume matching none of the current set is a domain rejection (`WorkItemTransitionRejected`) that leaves the set intact; repeating the consumed condition is the only idempotent no-op; the aggregate retains the last consumed condition"; propagate to :219 and :838-840; flag epics NFR-9 for the PM.
