## Cause and correction

The retained runtime-family head is a shared SDK adapter defect. Redis records a native `first-write` field for conditional creation. When a shared receipt already exists, an empty-ETag conditional save can raise an Internal transport error instead of returning CAS false. The coordinator then cannot reach journal dequeue. The live diagnostic trace captures `failed to set key` at that receipt save. Redis's [v1.18.3 adapter source](https://raw.githubusercontent.com/dapr/components-contrib/v1.18.3/state/redis/redis.go), especially its Set error classification and parseETag implementation, explains the empty/nonempty ETag distinction. SDK provider documentation (`docs/concepts/choose-the-right-tool.md`) also supports PostgreSQL, Cosmos DB and DynamoDB, so the correction avoids assuming Redis's initial ETag value.

The SDK now resolves only a failed empty-ETag create through a strong read of the same key. A nonempty ETag proves the addressed key exists and permits CAS false. Missing or unreadable evidence preserves the original write failure. Caller cancellation remains a failure, including cancellation during read-back. Typed, expiring and raw coordinated writes share this rule. Wire ETags, successful create behavior, current/stale update behavior, checkpoint ordering and receipt validation are preserved. Temporary diagnostic exception tracing was removed before packing the final candidate.

The faithful replay restores the retained Redis hashes with their original native fields, including `first-write`. Public 3.124.0 leaves the date head at position 11 and six pending entries. The candidate removes that head, leaving five entries and reaching the deliberately stopped next parent fold. Both retain checkpoint position 11 / owner sequence 5 and exactly the same receipt hash (`E1C1F820369FCBBD14545C1A15800A424F58A864C8881D61F7E873F8E6ECC7C2`). The original producer was independently downloaded from the official NuGet flat container, and its Client DLL matches the original probe. Earlier JSON-only reseeding dropped the native field and did not reproduce the defect; its probes are retained without treating them as the faithful reproduction.

Works now retries contextual workload HTTP 401/403 as unavailable authority while preserving corrupt-event exclusions. Recovery accepts depth rejection only when resulting depth exceeds the maximum. Reader/runner regressions cover missing/zero initial effort and missing/equal/decreasing depth values, along with valid committed rejection no-ops. They assert checkpoint, quarantine/park reason and absence of submissions. The deferred-work ledger separates resumed review runs, uses repository-relative source-spec paths, and corrects index-write provenance to in-story commit `07e23a6` and the earlier low rejection.
