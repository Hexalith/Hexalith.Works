## Intent

**Problem:** EventStore has stream paging and effect receipts but no checkpointed process runner. Works-owned Reactor recovery cannot satisfy AD-20 R7–R8 through the SDK, and failed work can strand silently.

**Approach:** Publish a bounded, checkpointed EventStore runner for domain-supplied translations and trusted effects, with periodic reconciliation, durable unresolved evidence, readiness, and disposition hooks.

## Boundaries & Constraints

**Always:** Treat `FromSequence` as exclusive; reuse `LastSequenceReturned` without increment. Validate identity, continuity, and full state-affecting decode before checkpointing. Derive effect IDs from stable source coordinates, kind, target, and ordinal. Advance only after all effects have terminal receipts or the envelope is durably quarantined. Bound pages, retries, and scans; rediscover work after restart. Unresolved or incomplete scans degrade readiness with bounded reason metrics and alert signals. Authenticate and audit disposition, fail closed on audit failure, and re-enter the same validator. Keep new durable types synthetic until AD-28 owner policy and restore proof permit real data.

**Never:** Reimplement receipts, trust gateway status or broker order, acknowledge unrecorded failure, copy Works decisions into EventStore, expose payloads in diagnostics, or remove the Works host. Platform owns production alerts/admission; Story 4.15 supplies Works translators.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
| --- | --- | --- | --- |
| Long source | Full and partial pages | Every position processed; cursor equals last returned sequence | Invalid page quarantines |
| Ambiguous crash | Effect commits before checkpoint | Identical replay settles by receipt, then advances | Unknown result retries |
| Terminal outcomes | Rejection or no-op receipt | Record outcome and advance without re-handling | Unknown disposition quarantines |
| Duplicate/reorder | Old delivery or concurrent runner | CAS prevents regression; receipts prevent duplicates | Conflicts quarantine |
| Bad evidence | Foreign, malformed, unknown event | Durable source-scoped record and degraded readiness | No skip or coercion |
| Parked source | Retry exhausted or dependency down | Periodic discovery and alert persist | Audited disposition revalidates |
| Denied disposition | Wrong tenant or failed audit sink | No record change or source disclosure | Fail closed |

**Acceptance Criteria:**
- Given a multi-page source with a crash after target commit, when the runner restarts, then the same effect identity replays to one durable target outcome and the checkpoint reaches the final validated position without a skipped envelope.
- Given invalid evidence or exhausted retry, when recovery runs again, then a tenant-scoped unresolved record remains discoverable, readiness and alert evidence remain degraded, and authorized audited disposition re-enters the validator.
- Given the published EventStore SDK contract and a synthetic pure translator, when a package-only consumer runs it, then process execution needs no Works runtime code and exposes the R7–R8 producer API for Story 4.15.

## Design Notes

One per-source CAS record owns checkpoint and unresolved evidence; target receipts close the crash gap. Discovery indexes are aids: incomplete source scans cannot report Ready. The authoritative catalog and durable candidate registry each expose bounded pages with continuation. Persist their continuation state across passes and restart; rotate fairly so a full first page cannot starve later or parked sources. Keep candidate index pages bounded individually while allowing additional pages. A source cannot be processed until its candidate page is durable. Register a new tenant only after its first page exists, and recover a partial publication without losing other tenants' scan progress. Readiness becomes stale and degraded if a scheduled pass does not complete within a bounded interval; direct disposition invalidates a previously healthy snapshot until the source is rescanned.

The candidate marker is only an optimization: recover a marker-write crash by searching already linked pages before append, so repeated registration never creates duplicate entries. Validate persisted index pages against a stable storage-format ceiling, not the current request page size. If a persisted tenant page is unreadable, record a bounded unresolved scan reason and advance the sweep to later tenants; retry that tenant in the next cycle. Process multiple candidate pages within a bounded per-pass work budget so large registries complete in operationally useful time. A completed catalog or persisted sweep waits for the other sweep; count each source once per cycle and persist bounded reason counts alongside unresolved totals. Treat concurrent sweep CAS loss as another replica's progress, retaining degraded local status until a coherent sweep is observed.

Coordinate processing and disposition per source with durable ownership/fencing so no owner can clear another owner's quarantine, report it as resolved, or submit later effects after losing ownership. A read failure with unknown position must not apply stale retry evidence to an advanced checkpoint. Bound translated effect count and command bytes per envelope and page; capture owned command bytes before translating the next event. Keep limits and scan intervals within practical operating maxima. Disposition may revalidate only a previously published candidate after authorization and audit. On disposition, force a fresh coverage cycle before readiness can become healthy, even if the old sweep was near completion.

No configured source budget may strand a full catalog or candidate page at the same cursor. Persist an entry offset or enforce a compatible minimum with a fair retry at the next pass; prove later-page source execution with nonzero checkpoints, including after an unreadable earlier tenant or candidate page. Require catalog continuation that remains valid when entries before the cursor are added or removed; keyset or snapshot cursors qualify, offset cursors do not. Bound each external catalog, registry, stream, and translation wait and retain degraded evidence when a dependency hangs. A candidate page unreadable at page N must not prevent probing page N+1 when that sequential page exists.

Treat disposition as a recoverable multi-record operation: make a durable pending/invalidation signal visible to all readiness readers before source mutation, keep it degraded through concurrent sweeps and crashes, and clear it only after a fresh scan of the changed source. Audit still precedes mutation. A published candidate marker is sufficient membership evidence when an unrelated earlier registry page is unreadable. Obtain each trusted effect's delegation context immediately before submission from a separate provider; the translator remains pure and supplies only deterministic effect data. Validate sweep flags, timestamps, cursors, and pending state together so malformed control records cannot report Healthy.

Publication must have a durable discoverable source identity before any multi-record index step can orphan it. A catalog observation cannot advance past failed publication without retaining that identity for retry even if the catalog removes it. Test crashes after every candidate page, marker, tenant, and link write, followed by catalog removal. An already linked page that reads null is incomplete or corrupt evidence, not a normal end; distinguish it from an unlinked end and continue probing reachable sequential pages while readiness stays degraded. Validate persisted tenant strings against canonical identity grammar and reject cursor offsets greater than the page length.

All paths that can newly expose an unresolved source or candidate must invalidate completed coverage before their source or registry mutation becomes visible. This includes direct runner calls, not only hosted scans and disposition. Reconciliation must count a source's latest durable state coherently with that invalidation, so a concurrent Active-to-Retrying change cannot be reported healthy. A recovery worker must claim an unapplied disposition generation before source mutation and must lose its authority after another worker applies and freshly covers it. Hosted stop must be visible to the local readiness check immediately; persisted sweep age still protects other replicas and hung workers.

Use per-operation deadlines and a bounded source service quantum that can checkpoint already validated envelopes before cumulative page work expires. Do not repeatedly abandon a valid multi-envelope page with zero progress. Classify timeout before evidence validity as retryable, and distinguish delegation-provider errors from target effect conflicts. Validate a null receipt as invalid evidence. A changed retry setting must not let an already exhausted Retrying source execute again.

Candidate registration must avoid a full historical page traversal per source while preserving deduplication after marker-write crashes. The supported source count, page capacity, per-pass work, scan interval, and freshness deadline need a documented, validated relationship: an admitted supported catalog can complete coverage within the readiness window, while capacity overflow remains explicitly degraded without silently dropping work. Retention stays under AD-28 owner policy; do not assume historical records can be erased to meet the bound.

Publication is complete only after both exact markers have been read back as durable; a rejected marker CAS can mean either a competing successful write or an absent marker, so verify rather than discard the result. Retain the pending source identity through bounded, resumable historical repair. A catalog publication failure contributes one unresolved source per cycle and must yield fairly to other sources. Catch tenant and candidate tail-read failures separately from missing pages, persist a bounded reason, and continue to later reachable pages without clearing the failure on an incomplete scan.

Treat gateway corruption reason codes as source evidence, not a generic outage. Publish unresolved coverage before the first target call even when the last source status is Active. Renew ownership after a near-deadline submission and before checkpoint CAS, or validate a sufficient margin. Keep each source's wall-time service quantum finite while durably checkpointing completed envelopes. Catalog page size, network latency, repair cost, effect count, and per-operation deadlines belong in supported-capacity math. Serialized envelope metadata and encoded command names count toward documented byte limits. A valid nonempty head resets prior retry evidence before new translation work.

On a validated nonempty page, clear retry attempts caused by stale source-read evidence, but preserve attempts for the same failed checkpoint/envelope until durable progress changes its identity; this reconciles fresh-head reset with a finite retry budget. A failed new-page CAS must be followed by exact readback before a parent link; a linked missing page remains a repairable unresolved condition under the durable publication intent. Tail hints may be stale after a crash, so append scans need a persisted bounded continuation rather than one registration walking all historical pages. Capacity limits may degrade service but must retain every partially attempted source's discoverable identity. Account for publication and disposition repair in the same fair pass budget as normal candidates. Treat malformed gateway response JSON as invalid source evidence. Use monotonic elapsed time for source quantum, and isolate a synchronous-blocking external adapter from the scan deadline. Verify registered operator and readiness compositions through the host container.

Maintain a pending source-transition marker in durable sweep state from before source mutation until fresh coverage includes the mutation; a mere generation reset is not enough because another replica can complete between writes. Repair queues need their own advancing cursors, and a catalog entry with a durable pending publication can be passed so later entries receive service. Keep pending publication identities under a practical state-item bound; when admission is full, reject the new source before any index write, leave its catalog continuation unadvanced, and retain degraded coverage. A linked missing page has unknown historical contents and must stay unresolved unless exact contents are independently proven; bounded persistent probing continues later reachable pages and eventually yields to the next tenant. Synchronous adapter isolation must have bounded worker admission and must not detach effectful state or target writes that could outlive their ownership deadline. External authorization and audit waits need deadlines before mutation. Future completed-sweep timestamps are not fresh. A null delegation result is an unavailable delegation, not an uncertain target effect.

A busy source is unresolved coverage even when its last durable status is Active; observe it again after its owner completes. Persist enough registry-root and tail evidence to distinguish an empty index from a missing page zero and to continue through a finite run of absent linked pages toward a known later page, retaining an unresolved reason. A source contributes at most one observation and one source-run attempt per cycle across catalog and candidate sweeps, including operational failures. Keep negative disposition membership bounded without losing marker-write crash recovery. Renew the sweep lease while a bounded source run is in progress, and verify ownership before writing coverage. Set the requested envelope count so any allowed translated command bytes fit the page budget, or yield with a durable checkpoint before a valid envelope would exceed that budget; never quarantine a valid envelope solely for exceeding the chosen service quantum. Renew source ownership after delegation and before submission. New-tenant publication with a fresh durable intent must skip historical tenant search; a retry after a write crash still deduplicates. Reject ReadinessMaxAge equal to ReconciliationInterval. Test a busy Active owner, missing root with retained candidates, duplicate catalog/candidate failure, several consecutive missing pages with a later retained source, near-expiry delegation, long sweep operation, valid command-budget progress, many-tenant registration, negative membership cost, valid byte-capped gateway requests, and translator buffer mutation during delegation.

A transition handoff is a mutation fence, not merely a cycle generation: assign a fresh token on each source update attempt and clear only the exact token observed in the latest durable source state. Make the observation read, source marker, and handoff removal safe against a second mutation between those operations. Bound total serialized sweep-state bytes before every admission; finite pending-count limits alone do not bound the record when source identifiers reach their allowed lengths. If the observation budget fills, retain its durable scan position, yield, and resume fairly. A timed-out pure read may leave an uncooperative worker alive, so cap those workers, refuse further admission promptly when exhausted, keep readiness degraded, and surface a bounded diagnostic reason; never treat queue waiting as source progress. Document the limit of in-process isolation and require cooperative cancellation for supported adapters. Count every actual catalog request in the supported-capacity formula, including repeated requests when a pass cannot retain its page. Hosted pass exceptions must set local failure evidence before sleeping, and a subsequent successful pass clears it. Host startup must resolve all adapters required for operator disposition. Sweep validation and readiness must use the same registered clock, and persisted index pages must contain unique identities.
