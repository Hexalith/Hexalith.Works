# Works SDK projection and query adoption (Story 4.14)

## Mode and ownership

`Works:Projection:UseSdkDelivery` defaults to `false`. In that mode Works keeps its existing `/project` writer, schema-v2 and legacy readers, and reminder and Reactor composition. Set it to `true` only in an isolated migration fixture: the host disables the bespoke writer, exposes the EventStore named epoch handler for `works-runtime-v3`, and selects SDK generation reads for queries, reminder discovery, and cascade descendants. The handler's projection type, scope family, and control index all identify that one runtime family. EventStore owns lease fencing, journal, physical generation keys, checkpoints, promotion, abort, and read selection. Works returns logical batch operations after folding domain evidence.

The runtime family holds a tenant queue and membership index, per-item roll-ups, relationship topology, pending-date entries and cleared-await sequence tombstones, per-item parking records, and source context used to fold individual SDK envelopes. A rebuild stages those documents as one manifest. It leaves the pre-cutover schema-v2 and legacy keys intact for full restore. An incomplete, malformed, gapped, or conflicting candidate fails before promotion. Ordinary delivery uses the same fold to update the selected generation; duplicate deliveries do not logically advance the checkpoint twice. `Works:Projection:MaxUndecodableEventDispatchesBeforeParking` remains the bounded terminal parking threshold.

## Query authority

SDK `/query` ingress accepts only the authenticated EventStore gateway workload named by `Works:Query:GatewayWorkloadId` (default `eventstore`). The gateway must stamp the authenticated workload and original actor fields. Works uses the published Parties client to resolve the requested `partyId` under the exact query tenant and actor; the client is registered at the host edge and calls the canonical Parties gateway. Configure `Works:Query:PartiesGatewayBaseAddress` as an absolute URI, or provide `EventStore:CommandGateway:BaseAddress`. The current Works authorization handler forwards an inbound authenticated Bearer. If the bearer, gateway URI, current binding, or Parties service is unavailable, Executor authorization fails before any Works state read. A caller's `UserId`, payload role, or `IsGlobalAdmin` flag is insufficient. The EventStore producer's `DomainServiceWorkloadAssertionHandler` removes human `Authorization` on canonical domain-service invocation, so a real delegated Executor cannot yet reach the Parties gateway through this forwarding transport. A supported service-to-service identity-read admission path or approved delegated transport must be composed before SDK query mode is admitted.

Verified Executors may read their own Assigned work and the tenant's Queued work. Full tenant results require an exact workload in `Works:Query:PermittedCoordinatorWorkloads`; its default is empty. Related documents are read from one SDK selected generation. Responses mark prior-generation data stale and failed generation reads unavailable. Reminder recovery discovers tenants from the SDK control index, reads pending and parking documents from one selected generation, and still refolds each candidate's authoritative stream. Cascade recovery retains its authoritative stream read and pins the related queue and roll-up read.

## Migration and rollback

This story does not authorize production activation. Before any later cutover, capture a restorable point-in-time copy of the **entire** EventStore/Works state store, its activation marker, projection metadata, journals, checkpoints, source events, and the compatible fleet/configuration; retain the replay source and verify the restore in an isolated environment. Quiesce the old Works delivery path at the migration fence, deploy one SDK writer and matching readers together, capture the sealed tenant inventory, stage and promote the full family, and check control-index membership, checkpoint heads, parking/readiness, and query freshness before admitting traffic. Abort a failed candidate and keep the previous generation serving marked-stale reads. Do not run old and new writers against the same live tenant.

The EventStore v2 activation marker prevents an in-place downgrade. Rollback restores the **complete pre-cutover store and fleet snapshot together**, including the marker and all projection/control/checkpoint data, then replays retained source events through the pre-cutover writer and verifies legacy read models before reopening traffic. Merely switching `UseSdkDelivery` off against a v2-activated store is not rollback. Any production marker, deployment, real authority provisioning, and Platform R3–R5 admission remain gated by Story 4.16 and AD-28.

## Consumer evidence and limits

The Release consumer compiles against the published EventStore `3.120.0` and Parties.Client `1.2.1` packages. Focused tests exercise SDK journal/catch-up/checkpoint/control index/redelivery, restart, rebuild promotion and abort, candidate gap rejection, and coordinator and Executor query policy. With `WORKS_SDK_DAPR_GRPC_ENDPOINT` set to a live Dapr sidecar using Redis `statestore`, the focused test also persists the complete family, promotes it, creates a new Dapr client/store/coordinator, drains concurrent delivery, and checks the selected generation and checkpoint. The published `3.120.0` coordinator lacks the current source tree's `DeliveryGap` and `RebuildRequired` dispositions. A focused package test confirms it journals an ordinary sequence gap; Works' strict fold then durably parks the delivery, leaves the prior visible queue unchanged, and reports degraded query metadata. Recovery of that aggregate requires an authoritative rebuild.

`WorksSdkProtectedHttpTests` starts a real local Works host with development-only synthetic credentials. It verifies the protected `/query`, `/project/v2`, and conflict `/project` routes against missing channel tokens, missing and wrong-operation assertions, a valid gateway assertion, and a foreign caller. The valid query is intentionally denied by query policy before state access. `WorksSdkRollbackRestoreTests` uses an explicitly isolated Redis port: it snapshots every serialized key, exercises SDK state and the actual `projection-delivery-writer-protocol` key, restores the entire pre-cutover keyspace, selects the legacy Works writer and reader, and replays retained synthetic source events. Run `tests/Hexalith.Works.IntegrationTests/run-sdk-rollback-restore.sh` with Docker and the local Dapr runtime installed; the script starts and cleans up its isolated Redis container and Dapr sidecar, runs the live Dapr/Redis projection suite, then runs the restore/replay fixture. The test guard requires `WORKS_SDK_ROLLBACK_ALLOW_ISOLATED_FLUSH=true` and a non-default loopback Redis port because it flushes that database. This proves the Works state/configuration sequence in an isolated fixture; it does not prove a deployed EventStore/Works fleet snapshot, source archive, or operational cutover. Those admission proofs remain required.

The published EventStore Server `3.120.0` assembly decompiles to a `DomainServiceWorkloadAssertionHandler` that removes `Authorization` for canonical domain-service calls. The receiver also rejects a human bearer alongside a workload assertion as conflicting credentials: `FrozenSdkRejectsHumanBearerOnAuthenticatedQueryIngressBeforeWorksStateAccess` proves the protected HTTP route returns 401 without reading Works state. Published Parties.Client `1.2.1` `HttpPartiesIdentityClient` posts `ResolvePartyIdentity` through its injected `HttpClient`, which can mechanically carry a separately configured genuine service credential. It does not require forwarding the original human token. The published `IIdentityGatewayAdmission` seam can independently authorize a trusted reader and sign target-actor evidence. However, the frozen canonical gateway query route accepts the JWT bearer default policy and excludes Dapr workload principals, while the existing Platform identity reader policy recognizes only an authenticated Dapr workload in `ReaderSources`. An ordinary service bearer alone does not meet that admission policy. The missing supported gateway/identity-authority composition is an admission blocker; a package-version change is not inherently required.

The additional authority tests use the actual published Parties client and Works authorization handler against a synthetic HTTP gateway at the adapter-policy boundary. They verify current canonical actor/Party binding, expiry, custody, tenant/Party/actor mismatch, restricted or erased identity, stale/degraded identity responses, and missing or rejected bearer authority. Successful synthetic queries read persisted SDK state and checkpoints; they do not demonstrate successful Executor access through the protected SDK route. Gateway-only enforcement also covers `/query/` and case-insensitive route spellings. SDK detail reads report unavailable when the roll-up identity, status, or source watermark disagrees with the queue used to authorize that Executor.

Ordinary delivery preserves every persisted parking disposition while refolding the tenant family; a healthy envelope for another aggregate cannot clear terminal parking or its degraded query warning. A complete authoritative rebuild remains the route that can reset parking.
