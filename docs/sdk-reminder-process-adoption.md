# SDK reminder and process adoption

Story 4.15 adds an exclusive opt-in recovery runtime. The default remains the legacy host. Enable both `Works:Projection:UseSdkDelivery=true` and `Works:Recovery:UseSdkRuntime=true` together. SDK mode validates the final service graph after host customization and the actual resolved hosted services in the generic host lifecycle before any hosted StartAsync, including instance and factory registrations, refusing legacy reminder actors, schedulers, dispatchers and hosted writers in either registration order. EventStore owns actor reminders, periodic discovery, leases, checkpoints, receipts, retry/parking, quarantine and readiness. Works supplies read-only adapters and clock-free domain decisions.

## Durable behavior

Create and reschedule optionally persist `WorkItemExpirySchedule(EffectiveExpiryUtc, ScheduleToken, Revision)` on their existing command/event types. The instant is resolved upstream, zero-offset UTC, with the SDK schedule token bound to tenant, item and revision. The pure aggregate checks token, monotonic revision and exact scheduled-expiry witness without reading a clock. Historical null fields retain historical behavior; no TTL is inferred from DueDate. A replacement schedule cannot silently drop an existing witness. The six changed command/event records retain their original compiled constructors and deconstruction overloads; additive expiry fields retain historical null serialization.

The reminder adapter refolds complete authoritative item streams on every call, emits every current date await in stable order, and emits the current explicit expiry witness. Every encountered non-null persisted expiry witness is validated before later history can replace or hide it. The same pure replacement validator used for commands enforces increasing revisions and prevents established witnesses being dropped; a non-null committed expiry must match the preceding current schedule. Historical null and witnessless delegated cascade expiry remain readable. Required reference members, nonempty suspension collections, explicit rejection booleans and closed Works full/short event names are checked through a recovery-only decoder before decoded no-ops, without changing the legacy/4.14 readers. Restored reminder entries reject blank committed message IDs while preserving historical null IDs. Canonical HTTP `404 missing-stream` is retryable only for the specifically committed SpawnChild-related child awaiting separate creation; missing source/parent history and other corruption retain their fail-closed behavior. Terminal state clears valid intents. A new suspension at the same date gets a new envelope position and identity. The process adapter decodes every envelope, including rejection no-ops, and uses envelope SequenceNumber and MessageId rather than payload Sequence. Related parent/child streams must be complete, contiguous, same-tenant and identity-bound. Cascades enumerate committed direct-child relationships conservatively so a receipt replay remains identical after the target has become terminal. Target validation determines whether the command changes domain state.

The SDK process catalog and optional reminder target catalog use existing `works-runtime-v3` family control membership and selected generation. Terminal and expiry-only members remain discoverable. Catalog keys advance strictly. Additive `ProcessSourcePage.IsIncomplete` releases validated healthy scopes while the SDK records unresolved discovery for unavailable scopes. Process sweep state and reminder catalog state retain that signal across restart. At the end of the available keyspace the SDK restarts discovery at the head, so new healthy members before a previous cursor are found despite a persistently degraded tenant. The additive SDK partial-availability control-index read validates the global registry first, excludes unreadable/malformed tenant tombstones, and returns healthy live tenants with an explicit incomplete signal. Registry, tombstone and complete tenant-family acquisitions use a separate SDK discovery pool of sixteen slots with 100 ms whole-operation deadlines in batches of sixteen (at most sixty-four retained tenants). `ReadDiscoveryAsync<T>` bounds reconciliation/status, every epoch read and pinned generation read as one operation. Outstanding reads are fenced by actual store provider, store name and logical registry/tombstone/family identity across coordinator reconstruction; repeated attempts refuse without reinvoking a hung provider. Admission remains occupied through actual completion, independently of ordinary contextual slots. Late results are discarded and every newly admitted call reads fresh offboarding evidence. Complete family membership, including member uniqueness, validates before any member is returned; the existing all-or-error API stays compatible. Offboarded family membership is omitted and never re-created. Reminder reconciliation gives existing indexed witnesses and initial discovery independent finite service slices, indexed first. Discovery defaults to two pages of sixteen targets, a two-second service budget and two-second bounded operations (`CatalogPagesPerPass` 1..8, `CatalogPageSize` 1..64, `CatalogServiceBudget`/`CatalogOperationTimeout` 100 ms..30 s). The same page/target settings cap indexed attempts at their product (thirty-two by default), with a separate service budget and durable tenant/actor continuation. Each phase claims an owner/generation before work and conditionally commits only its exact revision: a conflicting completion or failure-cleanup proof is never re-merged. Abandoned writes cannot overwrite a newer claim or transition. A maximum 500 ms failure-evidence cleanup allowance follows an exhausted slice. Bounded keyed convergence admission prevents repeated detached work for a still-running actor. Host-local item pruning accumulates head-to-tail coverage across slices and invalidates that proof if a replica missed another owner's continuation. It persists a continuation for later passes/restarts; individual target publication failure cannot stop later healthy tenants, and the durable incomplete flag survives later-page failures and a healthy tail until a fresh complete sweep. Authoritative target convergence publishes retained work, so terminal/no-intent targets cannot consume candidate capacity ahead of active ones. A new pass immediately marks readiness pending before any catalog/index await; callback version and pruning rules are preserved. Provider admission remains bounded until non-cooperative operations actually complete. No unvalidated member becomes a candidate. Event delivery only durably marks candidates and requests reminder convergence; it does not submit a second process effect. Malformed callbacks cannot mark SDK work completed.

Before any target submission, the SDK copies and persists the bounded original effect plan in its CAS-owned source state. Its private evidence digest binds the committed envelope sequence, message, event type, encoded payload and versions together with the complete copied effects: kind, ordinal, target, command type and exact payload bytes. Retained effects pass current structural/count/byte limits before digest allocation; a changed retained effect quarantines before delegation or submission. Restart validates that binding and current byte/effect limits before replay, then acquires fresh delegation. This covers a competing ordinary resume consuming an await before the trusted command commits a no-op receipt: no domain event is required to reconstruct the plan. Current exact target validation remains authoritative; the original effect must receive its prior receipt before the checkpoint can advance. A disappeared authoritative head with a retained plan remains quarantined even when cancellation preceded a failure-sequence marker. The plan is removed atomically with a successful checkpoint, never stored by Works.

A successful target receipt is required before a process checkpoint advances. Lost response after target commit therefore replays the same effect identity and receipt. Quarantine/parking and incomplete scans degrade the corresponding SDK readiness checks; operator revalidation goes through the same runner validator after authenticated, audited disposition. Gateway terminal command status alone is not evidence of a trusted effect outcome.

## Supported engineering limits

Works' SDK profile supports at most **five direct-child effects per terminal envelope** by default: `EventStore:Processes:MaxEffectsPerEnvelope=5`, `OperationTimeout=00:00:00.500`, and `SourceServiceQuantum=00:00:15`. SDK validation charges translation, the retained-plan CAS, effect operations and checkpoint: `Q >= (4 + 5F) × T`, so five effects require at least 14.5 seconds. A sixth child under this profile quarantines the complete terminal envelope before any target submission; earlier decoded no-op envelopes may already be checkpointed. Source evidence and failure position remain retained for authorized recovery under a correctly sized profile.

SDK defaults for the other coupled settings remain finite: six supported retained candidates, a 30-second reconciliation interval, two-minute lease and five-minute readiness age. The SDK also enforces `N × (2Q + 16T) + N × T + ceil(4N/B) × I <= A - I` and `A > lease + I`. Explicit overrides must satisfy every relationship; raising fan-out alone fails startup. These are supported synthetic engineering budgets, not admission or expiry policy and not a claim of arbitrary fan-out. Over-population retains candidates and degrades readiness.

Every Works contextual stream read has a cumulative **4 MiB retained encoded-envelope** budget and **500 ms whole-read deadline**, including all pages and decoding. `Works:Recovery:MaxContextBytes` accepts 1 KiB..16 MiB; `ContextReadTimeout` accepts 100 ms..30 seconds. This bounds cumulative retained encoded context before Works domain decoding; it is not a total transport or process heap limit. The actual SDK HTTP client separately caps each buffered response at 16 MiB by default, and that response plus its deserialized current page can materialize before Works checks retained allowance. Supported peak accounting therefore allows up to sixteen admitted contextual acquisitions, each with that independent response buffer/current-page allocation, retained context up to the configured allowance, decoded domain objects and bounded temporary encoded sizing. Discovery has its own sixteen slots and does not consume this contextual pool. Neither allowance is silently lowered for other SDK consumers or 4.14. Works checks raw variable-size fields against remaining retained allowance before temporary envelope sizing or domain decoding; every encoded envelope spends the cumulative retained budget before context is released. The SDK deadline's opt-in `ReadWithAdmissionAsync` bounds synchronous and non-cooperative gateway invocation with sixteen shared provider slots. Abandoned work retains its slot until actual completion; admission refusal remains retryable and cannot grow detached work without bound; SDK process translation additionally has one `OperationTimeout` for the complete relationship acquisition. Hosts must size both deadlines for their verified source population. Byte/page exhaustion and dependency outages remain retryable, then parked under SDK policy; foreign/undecodable or unsupported V1 metadata/payload evidence quarantines. A partial fold never reaches the pure translator or reminder scheduler.
